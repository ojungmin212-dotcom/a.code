## 2. 전체 구조

```
┌─ 리서치 프로세스 (scripts/run_research.py) ─────────────────────────────┐
│ 시장별 개장 60분 전 ─▶ Grok 3봇(감성·펀더멘털·반대논리) ─▶ 코드 결합     │
│                       예산 상한 검사 ──────────────┘          │         │
│                                                    논지(TTL) ▼         │
└──────────────────────────────────────── data/theses.sqlite ───────────┘
                                                     │ (60초마다 재로드)
┌─ 매매 프로세스 (run_mock.py / run_live.py) — 1개, 정책 레인 여러 개 ───────┐
│ 열린 시장 1개만 구독(국내 mc / 미국 RC) · 시세를 모든 레인이 공유(F9)       │
│   레인 1 Jev  → NH 모의/실계좌   + 섀도 판단(매 분 Jev 기록, F4)            │
│   레인 2 비교군 → 메모리 모의체결(같은 시세, 슬리피지 10bp 가정)             │
│   틱 ─▶ 1분봉 ─▶ 지표(코드) ─▶ 정책(Jev 또는 비교군) ─▶ 진입 신호        │
│                                                        ▼                 │
│              리스크 게이트(결정론적) ─▶ 시장가 주문(PLUG) ─▶ 결과         │
│                                                        ▼                 │
│   5초마다 잔고 대조 ─▶ 체결 확정 / 장부 불일치 시 정지                    │
│   손절·익절·마감 15분 전 청산 · 킬 스위치(data/KILL) · 총손실 시 전량 청산 │
│   모든 판단·주문·체결·1분봉 ─▶ 감사 로그(SQLite) ─▶ 리포트·승격 심사      │
└──────────────────────────────────────────────────────────────────────────┘
```

**설계 이유**
- **2-속도:** Grok은 느리고(수십 초) 비싸서 장중 분 단위 판단에 부적합. Jev는 빠르지만 스스로 정보를 찾지 않음 → 맥락(논지)은 Grok이 미리 만든다.
- **논지 공유 저장소:** Jev 정책과 비교군이 **같은 논지**를 읽어야 비교가 공정하고, Grok 비용도 한 번만 든다.
- **단일 프로세스 다중 정책(F9):** NH 웹소켓은 앱키당 세션 2개가 한도다. 또 두 정책이 **같은 계좌**로 주문하면 잔고 대조에서 서로의 보유분이 섞여 정지한다 → 브로커 주문은 Jev 레인만, 비교군은 같은 시세로 메모리 모의체결.
- **섀도 판단(F4):** 주문과 무관하게 매 1분봉 Jev 판단을 기록해 보정 표본을 늘린다. 실제 판단이 있던 봉은 건너뛰고, 논지 없는 섀도 전용 종목(기본 SK하이닉스·NAVER)은 `has_thesis=false` 로 분리 집계한다. 하루 1,200회·월 3,000원 상한.
- **시장 교대 단일 프로세스:** 국내(09:00–15:30)와 미국(23:30–06:00 KST)은 겹치지 않는다. 한 프로세스가 번갈아 운영해야 일일·총 손실 장부를 공유할 수 있다.

## 3. 설계 원칙 (협상 불가)

1. **LLM·Jev는 제안만, 주문은 코드만.** 결합·수량·한도 모두 코드.
2. **모든 외부 응답은 스키마 검증, 실패 = HOLD.** 재시도하지 않는다(비용 중복·신선도).
3. **기본값은 "아무것도 안 함".** 설정 누락·환율 낡음·예산 초과·응답 이상 → 매매 없음.
4. **모의 서버 외 주문 차단.** 운영 주문은 `allow_live` + `HARNESS_ALLOW_LIVE=I_ACCEPT_REAL_MONEY` + 승격 심사 + 확인 문구 입력.
5. **성공 판정은 HTTP가 아니라 주문번호·잔고로.** 결과 불명(UNKNOWN)은 재전송 금지, 잔고로 확정.
6. **멱등 주문 ID** = `정책-시장-종목-분-방향`, SQLite에 영속 → 재시작해도 같은 봉 재주문 불가.
7. **청산 경로가 없는 포지션은 열지 않는다.** 미국 매도 경로 미설정 시 미국 매수도 금지.
8. **장 마감 15분 전 전량 청산**(오버나이트 미보유).
9. **정지는 사람만 푼다.** 정지 상태는 재시작해도 유지, `resume.py`로 사유 기록 필요.
10. **모든 판단을 기록**한다(입력 상태·답·모델 버전·주문·체결·1분봉).

## 5. 의사결정 상세

### 5.1 리서치(Grok) → 논지
| 봇 | 도구 | 출력 |
|---|---|---|
| 감성 | web_search + x_search | `stance(LONG/NEUTRAL/AVOID)`, `confidence`, 근거·위험(한국어) |
| 펀더멘털 | web_search | 동일 |
| 반대논리 | 없음(비용 절감) | `invalidation_prob`, 반론 |

결합 규칙(`research.yaml` `aggregate`):
1. 어느 봇이든 `AVOID` 신뢰도 ≥ 0.6 → 거부
2. 반대논리 무효화 확률 ≥ 0.5 → 거부
3. 점수 = (감성 0.4 · 펀더멘털 0.6 가중, LONG=+신뢰도·AVOID=−신뢰도) × (1 − 무효화 확률) ≥ 0.45 → 논지 생성
4. 유효시간 180분, **장 마감을 넘지 않음**. 리서치 실패·예산 초과 시 **기존 논지 즉시 만료**
5. Grok은 종목을 고르지 않는다 — `universe`에 적힌 종목만 평가(종목코드 환각 방지)

### 5.2 Jev 정책 (signal_v1)
| 질문 | 타입 | 통과 조건 |
|---|---|---|
| `thesis_aligned` — 가격 흐름이 논지와 맞는가 | noul | ≥ 0.60 |
| `momentum` — 상승 모멘텀 강도(5단계) | score 0~4 | ≥ 2.5 |
| `regime` — 추세/횡보/급변 | choice | 급변 확률 ≤ 0.30 |

신뢰도 = 정합 확률 × (1 − 급변 확률). state = 논지 + 코드 계산 지표 + 최근 15개 1분봉.

### 5.3 비교군 정책 (AI 없음)
MA20 위 + 15분 수익률 > 0 + 거래량 비율 ≥ 1.2 → 고정 신뢰도 0.70.

### 5.4 공통 신호 생성
- 최소 1분봉 20개, 지표: 5·15분 수익률, MA20, VWAP, ATR14, 거래량 비율
- 손절 = 진입가 − ATR14 × 2, 익절 = 진입가 + 손절폭 × 2.5
- 국내는 **KRX 호가단위**로 반올림(손절 내림·익절 올림), 미국은 0.01달러

## 7. 주문·체결·장애 처리

| 상황 | 처리 |
|---|---|
| 주문 응답에 주문번호 있음 | ACCEPTED → 잔고 대조 대기 |

| 매도 대조: 잔고 감소 | 청산 확정, **손익은 직전 시세로 추정**(잔고에 체결가 없음) |
| 매도 대조: 60초간 변화 없음 | 다음 분 재주문(현금 계좌는 초과 매도 불가 → 중복 매도 위험 없음) |
| 하네스 종목 장부 ≠ 브로커 잔고 | **정지**(계좌의 다른 종목은 무시) |
| 같은 분 청산 재시도 | 분당 1회로 제한 |
| 킬 스위치 `data/KILL` | 정지 + 전량 청산 |
| 재시작 | 감사 로그로 손익·횟수·정지 복원, 미청산·미해소 있으면 시작 거부 |

## 12. 비판적 검토

1. **실서버 검증이 0건이다.** 코드 104개 테스트는 가짜 응답 기준이다. 필드명 하나만 달라도 동작하지 않는다(안전하게 멈추도록은 만들었다).
2. **50만원 장중 매매는 비용 부담이 크다.** 왕복 0.25~0.5% 비용에 리서치비 월 1만원(계좌의 2%)이 더해진다. 월 수익 1%(5,000원)로는 리서치비도 못 낸다.
3. **1종목으로는 통계적 판단이 어렵다.** 하루 거래 기회가 적어 6주·100회 기준을 채우기 어렵다. 기준을 낮추면 운과 실력을 구분하지 못한다. 종목을 늘리면 예산이 늘어난다 — 둘 중 하나는 포기해야 한다.
4. **LLM 장중 매매의 초과수익 근거는 약하다.** 장중 가격은 노이즈 비중이 커서 뉴스 해석의 우위가 드러나기 어렵다. 비교군 대비 우위를 승격 조건으로 둔 이유다.
5. **Jev는 출시 6주 된 얼리액세스 제품**이다. 서비스 변경·중단 시 HOLD로 떨어지지만, 운영이 멈춘다.
6. **Grok·X 검색 과금 구조가 최근 바뀌었다.** 실제 비용은 첫 호출 후 확인해야 한다.
7. **매도 손익이 추정치다**(잔고에 체결가 없음). 손실 한도가 실제와 조금 다를 수 있다.
8. **미국 운영의 추가 위험:** 새벽 무인 운영, 환율 수동 갱신, 소수점 주문 미지원(1주 > 25만원 종목 거래 불가), 휴장일 미반영.
9. **두 시장 분산은 소액에서 득보다 실이 클 수 있다.** P4 심사는 이를 검증하는 장치이지 성공을 보장하지 않는다.

**결론:** 이 하네스는 "Grok + Jev 조합에 우위가 있는가"를 **돈을 적게 잃으면서 검증하는 실험 장치**다. 수익 기계로 기대하면 안 된다.
