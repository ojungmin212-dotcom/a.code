# 주식 투자 하네스 설계 초안 (v0.1)

> 상태: 초안 · 작성일 2026-10-27
> 전제: **JEV의 정체는 확인되지 않음.** 본 문서는 JEV를 교체 가능한 어댑터 슬롯(§4.5)으로 두고 설계함. JEV가 무엇인지 확정되면 해당 절만 갱신.

---

## 1. 목표와 비목표

| 구분 | 내용 |
|---|---|
| 목표 | Grok 기반 분석 봇 여러 개의 의견을 구조화된 신호로 모으고, **코드로 된 리스크 게이트**를 통과한 주문만 실행 |
| 목표 | 모든 판단·주문을 재현 가능하게 기록(감사 로그)하고 성과를 정량 평가 |
| 비목표 | LLM이 직접 주문 API를 호출하는 구조 (금지) |
| 비목표 | 초단타/HFT (LLM 지연시간 수 초 단위라 부적합) |

비유: Grok 봇들은 **애널리스트 회의실**, 리스크 게이트는 **준법감시인**, 실행 엔진은 **트레이딩 데스크**입니다. 애널리스트는 의견만 내고, 주문 버튼은 준법감시인 승인을 거친 데스크만 누릅니다.

## 2. 전체 구조

```
 [데이터 수집]──▶[스냅샷 저장(시점 고정)]
                        │
          ┌─────────────┼─────────────┬──────────────┐
          ▼             ▼             ▼              ▼
     뉴스/X 감성봇   펀더멘털봇     기술적분석봇    반대논리봇(Bear)
          └─────────────┴──────┬──────┴──────────────┘
                               ▼
                    [집계기 / 심판봇]  ── 신호 JSON
                               ▼
                    [JEV 어댑터 슬롯]  (§4.5)
                               ▼
              [리스크 게이트 — 결정론적 코드, LLM 없음]
                               ▼
          [실행 엔진] ── 모의투자 → 소액 실거래 (단계적)
                               ▼
         [감사 로그 · 포지션 DB · 성과 평가 · 알림]
```

## 3. 설계 원칙 (협상 불가 항목)

1. **LLM은 제안만, 실행은 코드가.** 주문 권한은 실행 엔진에만 존재.
2. **모든 LLM 출력은 JSON 스키마로 검증.** 파싱 실패·필드 누락 시 해당 신호는 버림(=HOLD). 재시도 1회까지.
3. **시점 고정(Point-in-time) 스냅샷.** 봇에 주는 입력은 저장된 스냅샷만 사용 → 재현·백테스트 가능.
4. **기본값은 "아무것도 안 함".** 오류·타임아웃·불확실 → HOLD.
5. **킬 스위치.** 일일 손실 한도 초과, API 오류 연속 N회, 수동 플래그 중 하나라도 걸리면 신규 주문 중단.
6. **멱등성.** 주문마다 `client_order_id` 부여, 재시도 시 중복 주문 방지.

## 4. 구성요소 명세

### 4.1 데이터 수집 계층
- 시세(OHLCV), 재무제표, 공시, 뉴스, X(트위터) 게시물
- 각 수집 결과를 `snapshots/{date}/{ticker}.json` 형태로 해시와 함께 저장
- 출처·수집시각을 반드시 메타데이터로 보존

### 4.2 Grok 봇 (분석 에이전트)
xAI API(OpenAI 호환 형식)를 사용. 모델명은 설정 파일로 분리해 교체 가능하게 둠.

| 봇 | 입력 | 역할 |
|---|---|---|
| Sentiment | 뉴스, X 게시물 | 시장 심리·이슈 요약 |
| Fundamental | 재무, 공시 | 밸류에이션·실적 평가 |
| Technical | OHLCV + **코드로 미리 계산한 지표** | 추세·모멘텀 해석 (지표 계산은 LLM에 맡기지 않음) |
| Bear | 다른 봇들의 결론 | 반대 논리·리스크 지적 (확증편향 완화) |
| Judge | 위 4개 출력 | 최종 신호 집계 |

공통 출력 스키마(예시):
```json
{
  "ticker": "005930",
  "as_of": "2026-10-27T09:00:00+09:00",
  "bot": "fundamental",
  "stance": "BUY | SELL | HOLD",
  "confidence": 0.0,
  "horizon_days": 20,
  "key_reasons": ["..."],
  "risks": ["..."],
  "sources": ["snapshot_hash..."]
}
```

### 4.3 집계 규칙
- 1차: 단순 가중 투표(가중치는 설정값, 초기 동일 가중)
- Judge 봇은 **가중 투표 결과를 뒤집을 수 없고**, 신뢰도 하향만 가능 (LLM 단독 결정 방지)
- 봇 간 불일치가 크면(예: BUY·SELL 동시 존재) → HOLD

### 4.4 리스크 게이트 (순수 코드)
| 규칙 | 초기값(예시, 조정 필요) |
|---|---|
| 종목당 최대 비중 | 계좌의 10% |
| 1회 주문 최대 금액 | 계좌의 3% |
| 일일 최대 손실 | -2% 도달 시 당일 신규 진입 중단 |
| 최소 신뢰도 | 0.65 미만 무시 |
| 유동성 필터 | 일평균 거래대금 하한 |
| 거래 시간 | 장 시작/마감 직전 N분 주문 금지 |
| 손절/익절 | 진입 시점에 함께 등록 |

### 4.5 JEV 어댑터 슬롯 (미확정)
JEV의 정체에 따라 위치가 달라집니다. 확정 필요:

| JEV가 ~라면 | 하네스 내 위치 |
|---|---|
| 퀀트 지표/스코어링 엔진 | 봇 앞단 — 봇 입력 피처 제공 |
| 백테스트/평가 도구 | §6 평가 계층 |
| 증권사·주문 API | §4.6 실행 엔진의 브로커 어댑터 |
| 다른 AI 에이전트/프레임워크 | §4.2 봇 오케스트레이터 대체 |

인터페이스는 어느 경우든 `Protocol`(추상 클래스)로 고정해, JEV 교체가 다른 계층에 영향을 주지 않게 함.

### 4.6 실행 엔진
- 브로커 어댑터 인터페이스: `place_order / cancel / get_positions / get_balance`
- 국내 주식이면 한국투자증권 KIS Developers 등 **모의투자 계좌를 지원하는 Open API**로 시작 권장
- 단계: ① 모의투자 ② 소액 실거래 ③ 한도 확대 — 각 단계 승격 기준을 사전에 숫자로 정의

### 4.7 관측성
- 감사 로그: 입력 스냅샷 해시 → 봇 출력 원문 → 집계 결과 → 게이트 판정 → 주문/체결 전부 연결
- LLM 비용·지연시간·파싱 실패율 지표
- 알림(텔레그램/슬랙 등): 체결, 킬스위치 발동, 오류

## 5. 실행 주기 (예: 일 1회 스윙 전략)

1. 08:30 데이터 수집 → 스냅샷 저장
2. 08:40 봇 병렬 실행 (타임아웃 60초/봇)
3. 08:50 집계 → JEV → 리스크 게이트
4. 09:10 이후 주문 실행 (장 초반 변동성 회피)
5. 15:40 체결·포지션 정산, 일일 리포트

## 6. 평가와 검증 — **가장 큰 함정**

| 문제 | 설명 | 대응 |
|---|---|---|
| **LLM 미래 정보 누출** | 과거 데이터로 백테스트하면 모델이 학습 데이터로 이미 "결과"를 알고 있을 수 있음 → 백테스트 성과가 부풀려짐 | 모델 학습 컷오프 **이후** 기간만 유효한 검증으로 인정. 실질적으로는 **포워드 테스트(모의투자)가 주 검증 수단** |
| 비결정성 | 같은 입력에도 출력이 달라짐 | temperature 낮게, 출력 원문 저장, 동일 입력 N회 샘플로 일관성 측정 |
| 소표본 | 몇 주 수익률은 운과 구분 불가 | 최소 거래 횟수·기간 사전 정의, 벤치마크(지수) 대비 비교 |
| 비용 | 수수료·세금·슬리피지 미반영 시 과대평가 | 백테스트/모의투자 모두 비용 반영 |

핵심 지표: 벤치마크 대비 초과수익, 최대낙폭(MDD), 샤프비율, 승률·손익비, 봇별 기여도(어느 봇이 실제로 도움이 되는지).

## 7. 디렉터리 구조 (제안)

```
a.code/
├─ config/            # 모델명, 가중치, 리스크 한도 (YAML)
├─ harness/
│  ├─ data/           # 수집기, 스냅샷 저장소
│  ├─ bots/           # Grok 봇 프롬프트 + 스키마
│  ├─ aggregate/      # 집계·Judge
│  ├─ adapters/jev/   # JEV 어댑터 (미확정)
│  ├─ risk/           # 리스크 게이트 (단위테스트 필수)
│  ├─ execution/      # 브로커 어댑터, 모의/실거래
│  └─ observability/  # 로그, 지표, 알림
├─ eval/              # 포워드 테스트 리포트, 백테스트
└─ tests/
```

권장 스택: Python 3.12, `pydantic`(스키마 검증), `httpx`(API), SQLite→PostgreSQL(로그/포지션), APScheduler 또는 cron.

## 8. 단계별 로드맵

| 단계 | 산출물 | 완료 기준 |
|---|---|---|
| P0 | 스키마·리스크 게이트·브로커 인터페이스 | 리스크 게이트 단위테스트 100% 통과 |
| P1 | Grok 봇 1개 + 모의투자 연결 | 1주 무중단 운영, 파싱 실패율 < 2% |
| P2 | 봇 4종 + 집계 + JEV 연결 | 포워드 테스트 최소 8주 |
| P3 | 소액 실거래 | P2 결과가 사전 기준 충족 시에만 |

## 9. 솔직한 리스크 평가

- LLM 기반 종목 판단이 지수 대비 **지속적 초과수익을 낸다는 검증된 근거는 현재 부족**합니다. 이 하네스의 1차 가치는 "돈 버는 기계"가 아니라 **가설을 안전하게 검증하는 실험 장치**입니다.
- X 게시물 감성은 조작·노이즈에 취약합니다. 단독 신호로 쓰지 말 것.
- API 장애, 프롬프트 변경, 모델 업데이트만으로 성과가 바뀔 수 있음 → 모델 버전·프롬프트 버전을 로그에 고정 기록.
- 자동매매는 증권사 약관·API 이용 규정을 사전 확인해야 합니다.
