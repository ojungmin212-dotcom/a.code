## 1. 구성요소 사실 정리 (조사 결과)

### 1.1 Jev (TypeSafe AI)
- 2026-09-15 얼리액세스 공개된 **"System One" 결정 모델**. 자유 텍스트를 생성하지 않고 **타입이 정해진 답 + 확률**만 반환
- 요청: `state`(판단 대상 텍스트/JSON) + `questions`
  - `noul`: 예/아니오 확률
  - `choice`: 지정한 선택지 중 하나 + 선택지별 확률
  - `score`: 순서 척도 + 단계별 확률
- 공식 문서 권장: **큰 판단을 원자적 질문으로 쪼개고, 결합은 코드에서**
- 가격: 입력 10억 토큰당 $42, 출력 무료 (보도 기준)
- 지연시간: 약 70–500ms (**제3자 자료**, 공식 확인 필요)
- 주의: 벤치마크는 **벤더 자체 측정**. "환각 없음"은 스키마 밖 답을 못 낸다는 뜻이지 판단이 맞는다는 뜻이 아님. 직접 가입이 일시 중단됐다는 보도 있음 → **API 키 확보 여부 먼저 확인 필요**

### 1.2 나무 PLUG (NH투자증권)
- REST 방식 Open API, Python SDK `nhplug` (나무·N2 공용)
- 국내주식(`krstock`)·해외주식(`gbstock`) 주문 지원, WebSocket 실시간 27개 채널(체결가·호가·체결통보 등)
- **모의투자 서버**: `moapi.nhplug.com:8443`, 계좌구분 `03` (운영 도메인과 섞으면 실패)
- 호출 제한: 초당 5회 상한 (SDK 기본 4회 자동 스로틀)
- 토큰 유효 24시간
- ⚠️ **SDK는 HTTP 200이면 성공 여부를 판정하지 않음** → `rsp_msg` 검사를 하네스가 반드시 구현
- 주문 샘플 기본값 `dry_run=True`

비유: Grok은 **아침 회의에서 오늘 볼 종목과 논지를 정하는 리서치팀**, Jev는 **장중에 "지금 들어가도 되나?"에 0.3초 만에 예/아니오 확률을 주는 트레이더의 직감**, 리스크 게이트는 **"얼마까지"를 정하는 규정집**입니다.

## 2. 전체 구조 (2-속도 아키텍처)

```
 ┌──────────── 느린 루프 (Grok, 장 전 + 30분 주기 + 이벤트) ────────────┐
 │ 뉴스/공시/X ─▶ Grok 리서치봇들 ─▶ 관심종목 + 논지(Thesis) JSON         │
 │                (감성 / 펀더멘털 / 반대논리)        유효기간 TTL 부여     │
 └──────────────────────────────┬────────────────────────────────────────┘
                                ▼ (Thesis 저장소)
 ┌──────────── 빠른 루프 (Jev, 1분봉 마감 또는 체결 이벤트) ─────────────┐
 │ PLUG WebSocket 시세 ─▶ 코드로 지표 계산 ─▶ state 구성(Thesis+지표)     │
 │                       ─▶ Jev 원자 질문 ─▶ 확률 결합(코드) ─▶ 신호      │
 └──────────────────────────────┬────────────────────────────────────────┘
                                ▼
           [리스크 게이트 — 결정론적 코드, LLM/Jev 없음]
                                ▼
           [주문 엔진 — PLUG REST, rsp_msg 검증, 멱등키]
                                ▼
        [체결통보 WS → 포지션 DB → 손절/익절 감시 → 감사 로그·알림]
```

**왜 이렇게 나누나:** Grok 응답은 수 초~수십 초 걸리고 비용이 큼 → 장중 매 분 판단에 부적합. Jev는 빠르고 싸지만 **스스로 정보를 찾지 않음**(주어진 state만 판단) → 맥락은 Grok이 미리 만들어 둠.

## 3. Jev 질문 설계 (예시)

하나의 "매수할까?" 대신 원자 질문으로 분해:

| ID | 타입 | 질문 | 결합 시 역할 |
|---|---|---|---|
| q_thesis | noul | 현재 가격 움직임이 Thesis 방향과 일치하는가 | 필수 조건 (p ≥ 0.6) |
| q_momentum | score(1–5) | 최근 15분 모멘텀 강도 | 가중치 |
| q_news_shock | noul | state 내 최근 뉴스가 Thesis를 무효화하는가 | 거부권 (p ≥ 0.4면 진입 금지) |
| q_regime | choice(추세/횡보/급변) | 지수 장세 분류 | 급변 시 진입 금지 |

- 결합 공식은 코드로 고정하고 버전 관리 (예: `signal_v1`)
- Jev 확률은 **보정(calibration)이 금융 데이터에서 검증되지 않음** → 모의투자 기간에 Brier score / 신뢰도 곡선을 측정해 실제 적중률과 비교

## 4. 설계 원칙 (변경 없음 + 추가)

1. LLM/Jev는 제안만, 주문은 코드만
2. 모든 출력 스키마 검증, 실패 = HOLD
3. 시점 고정 스냅샷 저장
4. 기본값 HOLD
5. 킬 스위치
6. 멱등 주문 ID
7. **(추가) 브로커 응답은 HTTP 코드가 아니라 `rsp_msg`로 성공 판정**
8. **(추가) 장 마감 N분 전 전량 청산** (장중 전략이므로 오버나이트 미보유 — 미국장은 아침 6시 전 청산)

## 5. 리스크 게이트 (50만원 / 최대 손실 10만원 기준)

| 규칙 | 값 | 근거 |
|---|---|---|
| 총 손실 한도 (하드 킬) | 평가손익 **-100,000원** 도달 시 전량 청산 + 시스템 정지 + 수동 재개만 허용 | 사용자 지정 |
| 일일 손실 한도 | -15,000원 | 최악의 경우에도 최소 6거래일 이상 버팀 |
| 1회 거래 최대 손실 | -5,000원 (손절가로 수량 역산) | 일일 한도의 1/3 |
| 동시 보유 종목 | 최대 2개 | 소액이라 분산 효과보다 수수료 부담이 큼 |
| 종목당 최대 금액 | 250,000원 | |
| 일일 최대 거래 횟수 | 국내 6회 / 미국 6회 | 과매매로 인한 수수료 누적 방지 |
| 최소 기대수익 | 왕복 비용의 3배 미만이면 진입 금지 | §8 비용 문제 |
| 연속 손절 | 3회 연속 시 해당 시장 당일 중단 | |
| 시간 필터 | 장 시작 후 10분, 마감 전 15분 신규 진입 금지 | 변동성·청산 시간 확보 |

수량 계산: `수량 = floor(1회 최대손실 / (진입가 - 손절가))`, 종목당 최대 금액으로 상한.

## 7. 디렉터리 구조

```
a.code/
├─ config/              # 모델·질문·결합공식·리스크 한도 (YAML, 버전관리)
├─ harness/
│  ├─ research/         # Grok 리서치봇 + Thesis 스키마/저장소
│  ├─ decision/         # Jev 클라이언트, 질문 정의, 확률 결합
│  ├─ market/           # PLUG WebSocket 수신, 1분봉 집계, 지표 계산
│  ├─ risk/             # 리스크 게이트 (단위테스트 필수)
│  ├─ broker/           # PLUG 어댑터: 주문/취소/잔고, rsp_msg 검증
│  ├─ scheduler/        # 장 시간·휴장일·서머타임 처리
│  └─ observability/    # 감사 로그, 비용 집계, 알림
├─ eval/                # 포워드 테스트 리포트, 보정 분석
└─ tests/
```

스택: Python 3.12, `nhplug`, `pydantic`, `httpx`, `asyncio`, SQLite.

## 8. 비판적 검토 — 반드시 읽어 주세요

1. **50만원 장중 매매는 비용에 잡아먹힐 가능성이 큽니다.**
   - 해외 수수료 0.09%(편도, 보도 기준) + **환전 스프레드**, 국내는 매도 시 증권거래세(세율은 2026년 기준으로 별도 확인 필요)
   - 왕복 0.3~0.5% 비용이면, 하루 6회 거래 시 수익이 0이어도 비용만으로 하루 1~3%가 빠질 수 있음
2. **API 비용이 수익을 넘을 수 있습니다.** 월 1% 수익이면 5,000원인데, Grok을 30분마다 여러 종목에 호출하면 월 API 비용이 이를 초과할 수 있음 → **월 API 예산 상한을 하드코딩**(예: 월 1만원)하고 초과 시 Grok 주기 자동 축소
3. **국내+미국 동시 운영은 소액에서 득보다 실이 큼.** 자금이 쪼개지고, 환전 비용, 새벽 무인 운영 위험이 더해짐 → **국내 먼저, 미국은 2단계** 권장
4. **미국 주가 대비 금액이 작음.** 25만원으로는 고가 종목을 1주도 못 살 수 있음. PLUG API의 소수점 주문 지원 여부는 **확인하지 못했습니다**
5. **Jev는 출시 6주 된 얼리액세스 제품.** 성능 수치는 벤더 측정, 금융 판단 성능에 대한 독립 검증은 찾지 못함. 서비스 변경·중단 리스크 있음 → Jev 장애 시 HOLD로 떨어지도록 설계
6. **LLM 장중 매매의 초과수익 근거는 일봉 매매보다도 더 약합니다.** 장중 가격은 노이즈 비중이 커서 뉴스 해석 우위가 잘 드러나지 않음
7. 자동매매 관련 증권사 이용약관·API 이용 규정은 사전에 확인 필요

**결론:** 이 하네스는 처음 2–3개월 동안 수익을 내는 기계가 아니라 **"Grok+Jev 조합에 우위가 있는가"를 싸게 검증하는 실험**으로 운영하는 것이 맞습니다.

## 9. 로드맵

| 단계 | 내용 | 실거래 금액 | 다음 단계 승격 기준 |
|---|---|---|---|
| P0 | 리스크 게이트·PLUG 어댑터(모의)·스키마 | 0 | 단위테스트 통과, 모의 주문/취소/잔고 왕복 성공 |
| P1 | 국내 빠른 루프(Jev) + 규칙 기반 Thesis | 0 (모의) | 2주 무중단, 파싱/주문 오류 0건 |
| P2 | Grok 리서치 루프 추가 | 0 (모의) | **최소 6주·100회 이상 거래**, 비용 반영 후 KOSPI 대비 우위, Jev 보정 확인 |
| P3 | 국내 실거래 | 20만원 | 4주간 모의와 성과 괴리 작음 |
| P4 | 미국장 추가(모의 → 실거래) | 50만원 전체 | P3 기준 충족 |

**비교군(필수):** Grok/Jev 없이 동일 리스크 규칙 + 단순 규칙(예: 이동평균 돌파)만 쓴 전략을 병행 모의 운영해야 AI가 실제로 기여하는지 판단 가능.

## 10. 남은 확인 사항

1. Jev API 키 확보 여부 (직접 가입 중단 보도) — 안 되면 Vercel AI Gateway 경유 가능 여부

4. Grok API 월 예산 상한
5. 알림 채널 (텔레그램 / 슬랙 / 카카오)
