## 1. 완성도 판정

### 1.1 영역별 점수 (제 판단)

| 영역 | 가중치 | 점수 | 근거 |
|---|---|---|---|
| 설계·안전장치 | 15% | 85 | 손실 한도, 멱등 주문, 승격 잠금, 안전한 실패 기본값 |
| 코드 구현 범위(P0~P4) | 15% | 90 | 계획한 모듈 전부 존재 |
| 오프라인 테스트 | 10% | 70 | 104개 통과. 단, 운영 루프(runner)·실서버 통합 테스트 없음 |
| **외부 연동 실검증** | **25%** | **15** | 실서버 호출 0건. 오늘 공식 명세를 찾아 일부 근거 확보(§2) |
| 데이터·평가 체계 | 15% | 40 | 보정·비교군은 있음. 벤치마크·휴장일 캘린더 없음, 표본 부족 구조 |
| 무인 운영성 | 10% | 25 | 프로세스 감시·대시보드·자동 환율 없음 |
| 전략 우위 증거 | 10% | 0 | 모의 운영 0일 |
| **가중 합계** | | **≈ 45%** | |

**한 줄 판정:** 코드는 85~90%, **실제로 돈을 다룰 준비는 15% 안팎, 종합 약 45%** 입니다.

### 1.2 카파시 관점 — "실전 기준 약 20%"
- ✅ 끝까지 도는 뼈대와 **단순 기준선(비교군)** 이 있다. 레시피의 2단계는 잘 지켰다.
- ❌ **1단계(데이터와 하나가 되기)를 건너뛰었다.** 실제 시세 메시지·주문 응답을 한 번도 보지 않고 P4까지 쌓았다. 레시피 순서를 거꾸로 밟은 것이다.
- ❌ **평가 표본이 구조적으로 부족하다.** 1종목에 거래할 때만 기록하면 6주에 수십 건이라, 보정(Brier) 판단이 불가능하다 → F4로 해결 가능.
- ❌ 판단 기준값(0.6·2.5·0.3)은 데이터 없이 정했다. 지금은 "튜닝"할 단계가 아니라 "관찰"할 단계다.

### 1.3 머스크 관점 — "필요 이상으로 많이 만들었다"
- ❌ **5단계(자동화)를 2단계(삭제)보다 먼저 했다.** P3·P4 실거래 코드, 미국 시장, 3봇 구조는 데이터가 없는 상태에서 만든 "존재하면 안 될 수도 있는 부품"이다. *(제가 작성한 코드에 대한 자기비판입니다.)*
- ❌ **사이클 타임의 병목이 코드가 아니라 사람이다.** 장중에 스크립트 4개 실행 → 결과 전달 → 반영까지 하루 이상 걸린다 → F5·F1로 단축 가능.
- ✅ 요구사항은 일부 덜 멍청해졌다: 리서치 1종목, 장 전 1회, 승격 잠금.
- 제안: 삭제 후보 D1~D3(§4).
